# 实施顺序

每个 PR 只处理一个可独立验收的变更。上一 PR 的最终提交经 Codex Review 无未解决问题后，才开始下一 PR。依赖 PR 尚未合并时使用堆叠分支，保留各自差异；不以未审查代码部署生产。

1. Ubuntu CPU 运行环境：移除 Apple 平台和旧 CLI 兼容层，统一 Python 3.12 依赖安装与 Moon 任务，保留现有批次、克隆、断点续跑能力。
2. 私有执行控制仓库与单机 runner：公开 PR 不得接触共享生产主机。独立用户、systemd 资源限制、专用标签、校验安装包；通过手动 smoke 验收服务器执行。
3. 预设语音与韵律：复用视频项目的分句、停顿与校验方式，移除强制克隆和自动低质量降级，真实比较云端音色。
4. 转录与翻译质量：保留原始转录证据，升级可用模型，纠正专名、数字和语义；完整样品验收。
5. 日调度与容量：每天北京时间 00:00 执行，20 小时上限，防重入与续跑；实测 1/4 与一半资源下的中文音频产出时长和集数，再确定批次参数；修复发布顺序与 Pages 触发。
6. Web 数据契约：流水线输出单集目录、文字稿与中英字幕；只公开转换产物，测试数据完整性与路径。
7. React Web：参考 Fish Drama 的视觉方向，实现按系列分组、封面与基本信息、简单搜索、播放与进度记忆、双语文字稿、RSS 订阅。标准 i18n 以独立中英文字典存储映射，组件只使用 key，语言开关完整切换界面并记住选择。Moon 管理构建；用 Computer Use 检查桌面与手机尺寸下两种语言的渲染、布局和交互。

8. Web 发布：Pages 构建 React 产物并保留 RSS 与文字稿路径；验证真实线上页面。

前端采用 Vite + React。GitHub Pages 直接托管构建产物，无需为动态交互增加常驻 Node 服务。iOS 不在本次范围内。
